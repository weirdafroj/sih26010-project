## Q&A PREPARATION

### **Q: How does it work without internet?**
A: "The app runs fully locally using SQLite. All GPS tracking, photo 
capture, and form submission happens offline. When internet returns, 
our intelligent sync engine pushes data to the cloud. Only changed 
data syncs, not full replication - efficient even on 2G."

### **Q: What about data security and privacy?**
A: "End-to-end encryption, JWT tokens, role-based access control. 
Sensitive data (Aadhar) is masked in logs. Optional blockchain 
hashing for immutable record verification. DGFT and government 
compliance built in."

### **Q: Can it work on basic phones?**
A: "Yes! Built with React Native using lightweight libraries. We've 
tested on 2GB RAM phones. App size <100MB. Can run on 4G as well."

### **Q: How accurate is the GPS?**
A: "±5 meters average with our sensor fusion tech. We use accelerometer 
and compass data alongside GPS. Manual point adjustment is available 
for surveyors if needed."

### **Q: How does AI improve accuracy?**
A: "We train models on satellite imagery to recognize agricultural 
plots. The AI generates a boundary suggestion. We then fuse it with 
the GPS data the surveyor traced, giving us both computer precision 
and human context."

### **Q: What's the cost to the government?**
A: "₹1 Cr per state for deployment. Breaks even in 2-3 years through 
saved manual labor costs. Long-term 70% cost reduction per survey."

### **Q: How do we convince farmers to adopt?"**
A: "Farmers see immediate benefit - official digital proof of ownership. 
No more disputes. They get a QR-coded certificate they can scan. 
Incentives: first state gets land certificate for free."

### **Q: What about existing paper records?"**
A: "Phase 1 focuses on new surveys. Phase 2 includes legacy 
digitization - we scan and AI-extract data from old documents. 
This can be done gradually, doesn't delay implementation."

### **Q: Integration with land registry systems?"**
A: "We provide APIs for existing government systems (ULPIN, Bhoomi, etc). 
Data can sync automatically. All standard government formats supported."

### **Q: Sustainability if team isn't available post-hackathon?"**
A: "Fully documented codebase on GitHub. Can be handed to government 
team for maintenance. Built on open-source tech, no vendor lock-in. 
Training provided for government engineers."

## PRESENTATION TIPS

### **Delivery**
- Speak clearly, pause for emphasis
- Make eye contact with judges
- Use hand gestures naturally
- Let passion show - this is a real problem!

### **Pacing**
- Don't rush through technical details
- Give judges time to understand each point
- Leave 2-3 minutes for questions

### **Visuals**
- Keep slides uncluttered (max 3 points per slide)
- Use color coding consistently
- Big, readable fonts (minimum 24pt)
- High-quality screenshots/mockups

### **Demo**
- Pre-record demo videos as backup
- Have phones/tablets fully charged
- Practice timing - demo should fit in 5 minutes max
- Have sample data ready
- Be ready to explain what's happening

### **Handling Skepticism**
Judge might say: "This seems too ambitious for a hackathon"

You respond: "Exactly - that's why we're focusing on the core MVP. 
We're not building a full government system in 2 days. We're building 
a working prototype that proves the concept, with full documentation 
for production deployment."
